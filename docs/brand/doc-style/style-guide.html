The Open DJ doc style

How Open DJ writes and lays out anything a person reads outside the deck: briefs, runbooks, status pages, artifacts and the app's own error screens. One look, one voice, answers first.

Reply by section id, for example "S4: drop the verdict top border". Each section is one decision you can keep, change or cut. To start a page, copy a template from S8; the folder's README says which file to use where.

S6Voice

Do
  • Lead with the answer, then the evidence.
  • Name things the way a person knows them: "the engine", not "the uvicorn process".
  • Short, active sentences. American spelling.
  • Dates with the weekday; times in UTC.
  • Say "I did not find" instead of "there is none".
Don't
  • Use the long dash characters (U+2013, U+2014). Use a hyphen, a comma or "--".
  • Use "not X, but Y" framing, scare quotes or "worth noting".
  • Use emoji as section markers.
  • Pad a pass with praise. A green check needs its control, not adjectives.

S7Evidence

  • Every claim that can drift carries a source line: a path and line, a PR, a session.
  • Every number has a hover title with its unit and its denominator.
  • Every "zero" or "none" names the control that proved the probe could fire.
  • Every page ends with a collapsed footer: What exactly was tested, or Not verified when corners were cut.

S9Open decisions

  1. D1

    Three oranges are live. App chrome uses amber #ffb43a, the setup page uses #f26b21, the mark uses terracotta #d97757 (and BuildIdentity.svelte falls back to it when --accent is unset). This guide uses #f26b21 for actions and keeps terracotta for the mark and the alpha badge. Pick one action orange for app and docs.

    apps/webui/frontend/src/app.css --accent · apps/desktop/setup/setup.css --accent · BrandLaunch.svelte fill

  2. D2

    Two font paths. Repo docs and in-app pages load the shipped offline subset through odj-doc.css. Artifacts can only load fonts from Google Fonts, so artifact-inline.html does that and carries its own copy of the rules. Open: keep two copies of the rules in step by hand, or generate the artifact file from odj-doc.css.

    docs/brand/doc-style/odj-doc.css · docs/brand/doc-style/artifact-inline.html

  3. D3

    Dark-first for docs too? The app is dark-first; most past artifacts were light-first. This guide follows the app and gives light readers the warm theme.
